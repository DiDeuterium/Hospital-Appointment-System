# 医院预约挂号系统数据库升级方案

## 一、升级目标

本升级方案仍然围绕“挂号预约”这一核心主题，不扩展到完整诊疗系统中的病历、处方、药品和真实支付模块。系统只增加挂号费模拟支付，用于演示挂号费确认流程，不调用第三方支付接口。

升级重点放在以下几个方向：

1. 补齐管理员角色，使科室、医生、排班、公告等管理操作有明确的数据主体。
2. 增强科室和医生的可用状态管理，避免删除历史数据导致预约记录无法追溯。
3. 增强排班管理，支持医生提交停诊申请或修改排班申请，并由管理员审核。
4. 增强预约记录，增加排队号、取消原因、更新时间等字段。
5. 增加系统公告，用于发布停诊通知、挂号须知、系统维护等信息。
6. 增加挂号费模拟支付记录，患者点击“模拟支付”后即视为支付成功。

升级后数据库共 9 张表：

```text
department                  科室表
doctor                      医生表
patient                     患者表
admin_user                  管理员表
schedule                    排班表
appointment                 挂号预约表
payment_record              挂号费模拟支付记录表
schedule_change_request     排班变更申请表
sys_notice                  系统公告表
```

## 二、建表脚本

```sql
-- ============================================
-- 医院预约挂号系统 — 数据库升级方案
-- 主题：排班发布、患者预约、模拟支付、排班变更审核、公告通知
-- ============================================

DROP TABLE IF EXISTS schedule_change_request;
DROP TABLE IF EXISTS payment_record;
DROP TABLE IF EXISTS appointment;
DROP TABLE IF EXISTS schedule;
DROP TABLE IF EXISTS doctor;
DROP TABLE IF EXISTS patient;
DROP TABLE IF EXISTS sys_notice;
DROP TABLE IF EXISTS admin_user;
DROP TABLE IF EXISTS department;

-- ================== 1. 基础信息模块 ==================

-- 1. 科室表
CREATE TABLE department (
    dept_id     INT          AUTO_INCREMENT PRIMARY KEY COMMENT '科室编号',
    dept_name   VARCHAR(50)  NOT NULL UNIQUE            COMMENT '科室名称',
    location    VARCHAR(100)                            COMMENT '门诊位置',
    description TEXT                                    COMMENT '科室简介',
    status      TINYINT      NOT NULL DEFAULT 1         COMMENT '状态: 1正常 0停用'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='科室信息表';

-- 2. 医生表
CREATE TABLE doctor (
    doc_id      INT          AUTO_INCREMENT PRIMARY KEY             COMMENT '医生编号',
    doc_name    VARCHAR(50)  NOT NULL                               COMMENT '医生姓名',
    gender      CHAR(1)      NOT NULL CHECK (gender IN ('M', 'F')) COMMENT '性别',
    title       VARCHAR(20)                                         COMMENT '职称',
    dept_id     INT          NOT NULL                               COMMENT '所属科室编号',
    password    VARCHAR(255) NOT NULL                               COMMENT '登录密码(BCrypt哈希)',
    avatar_url  VARCHAR(255)                                        COMMENT '医生头像URL',
    specialty   VARCHAR(500)                                        COMMENT '擅长领域',
    status      TINYINT      NOT NULL DEFAULT 1                     COMMENT '状态: 1正常 0停用',
    FOREIGN KEY (dept_id) REFERENCES department(dept_id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='医生信息表';

-- 3. 患者表
CREATE TABLE patient (
    patient_id INT           AUTO_INCREMENT PRIMARY KEY             COMMENT '患者流水号',
    id_card    CHAR(18)      NOT NULL UNIQUE                        COMMENT '身份证号',
    real_name  VARCHAR(50)   NOT NULL                               COMMENT '真实姓名',
    gender     CHAR(1)       CHECK (gender IN ('M', 'F'))           COMMENT '性别',
    phone      VARCHAR(20)   NOT NULL                               COMMENT '联系电话',
    password   VARCHAR(255)  NOT NULL                               COMMENT '登录密码(BCrypt哈希)'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='患者信息表';

-- 4. 管理员表
CREATE TABLE admin_user (
    admin_id    INT          AUTO_INCREMENT PRIMARY KEY COMMENT '管理员编号',
    username    VARCHAR(50)  NOT NULL UNIQUE            COMMENT '登录账号',
    real_name   VARCHAR(50)  NOT NULL                   COMMENT '管理员姓名',
    password    VARCHAR(255) NOT NULL                   COMMENT '登录密码(BCrypt哈希)',
    status      TINYINT      NOT NULL DEFAULT 1         COMMENT '状态: 1正常 0停用',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='管理员用户表';


-- ================== 2. 排班与预约模块 ==================

-- 5. 排班表
CREATE TABLE schedule (
    schedule_id INT           AUTO_INCREMENT PRIMARY KEY                 COMMENT '排班流水号',
    doc_id      INT           NOT NULL                                   COMMENT '出诊医生编号',
    work_date   DATE          NOT NULL                                   COMMENT '出诊日期',
    shift       VARCHAR(10)   NOT NULL CHECK (shift IN ('上午', '下午', '夜诊')) COMMENT '时段',
    total_quota INT           NOT NULL CHECK (total_quota > 0)           COMMENT '总号源数',
    rest_quota  INT           NOT NULL                                   COMMENT '剩余号源数',
    fee         DECIMAL(8, 2) NOT NULL DEFAULT 0.00                      COMMENT '挂号费',
    status      TINYINT       NOT NULL DEFAULT 1                         COMMENT '出诊状态: 1正常 0停诊',
    UNIQUE (doc_id, work_date, shift),
    CHECK (fee >= 0),
    CHECK (rest_quota >= 0 AND rest_quota <= total_quota),
    FOREIGN KEY (doc_id) REFERENCES doctor(doc_id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='医生排班表';

-- 6. 挂号预约表
CREATE TABLE appointment (
    appt_id       INT          AUTO_INCREMENT PRIMARY KEY COMMENT '预约单号',
    patient_id    INT          NOT NULL                   COMMENT '预约患者ID',
    schedule_id   INT          NOT NULL                   COMMENT '对应排班ID',
    queue_number  INT          NOT NULL                   COMMENT '就诊排队号',
    status        TINYINT      NOT NULL DEFAULT 1         COMMENT '状态: 1已预约 2已取消 3已就诊 4已过期',
    cancel_reason VARCHAR(255)                            COMMENT '取消原因',
    create_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE (schedule_id, queue_number),
    CHECK (queue_number > 0),
    FOREIGN KEY (patient_id)  REFERENCES patient(patient_id)   ON DELETE RESTRICT,
    FOREIGN KEY (schedule_id) REFERENCES schedule(schedule_id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='挂号预约记录表';

-- 7. 挂号费模拟支付记录表
CREATE TABLE payment_record (
    payment_id  INT           AUTO_INCREMENT PRIMARY KEY COMMENT '支付记录编号',
    appt_id     INT           NOT NULL UNIQUE             COMMENT '关联预约单号',
    amount      DECIMAL(8, 2) NOT NULL                    COMMENT '挂号费金额',
    pay_status  TINYINT       NOT NULL DEFAULT 0          COMMENT '支付状态: 0待支付 1已支付 2已关闭',
    pay_method  VARCHAR(20)   NOT NULL DEFAULT '模拟支付' COMMENT '支付方式',
    pay_time    DATETIME                                  COMMENT '支付时间',
    create_time DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    CHECK (amount >= 0),
    FOREIGN KEY (appt_id) REFERENCES appointment(appt_id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='挂号费模拟支付记录表';


-- ================== 3. 排班变更审核模块 ==================

-- 8. 排班变更申请表
CREATE TABLE schedule_change_request (
    request_id         INT          AUTO_INCREMENT PRIMARY KEY COMMENT '申请编号',
    schedule_id        INT          NOT NULL                   COMMENT '关联排班ID',
    change_type        TINYINT      NOT NULL                   COMMENT '变更类型: 1停诊 2修改排班',
    target_work_date   DATE                                    COMMENT '目标出诊日期(修改排班时使用)',
    target_shift       VARCHAR(10)                             COMMENT '目标时段(修改排班时使用)',
    target_total_quota INT                                     COMMENT '目标总号源数(修改排班时使用)',
    reason             VARCHAR(255) NOT NULL                   COMMENT '申请原因',
    status             TINYINT      NOT NULL DEFAULT 1         COMMENT '审核状态: 1待审核 2已通过 3已驳回 4已撤回',
    apply_time         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '申请提交时间',
    audit_admin_id     INT                                     COMMENT '实际审核管理员ID',
    audit_time         DATETIME                                COMMENT '审核时间',
    audit_remark       VARCHAR(255)                            COMMENT '审核意见',
    CHECK (change_type IN (1, 2)),
    CHECK (target_shift IS NULL OR target_shift IN ('上午', '下午', '夜诊')),
    CHECK (target_total_quota IS NULL OR target_total_quota > 0),
    FOREIGN KEY (schedule_id) REFERENCES schedule(schedule_id) ON DELETE RESTRICT,
    FOREIGN KEY (audit_admin_id) REFERENCES admin_user(admin_id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='排班变更申请表';


-- ================== 4. 公告模块 ==================

-- 9. 系统公告表
CREATE TABLE sys_notice (
    notice_id    INT          AUTO_INCREMENT PRIMARY KEY COMMENT '公告ID',
    title        VARCHAR(100) NOT NULL                   COMMENT '公告标题',
    content      TEXT         NOT NULL                   COMMENT '公告正文',
    is_top       TINYINT      NOT NULL DEFAULT 0         COMMENT '是否置顶: 1是 0否',
    status       TINYINT      NOT NULL DEFAULT 1         COMMENT '状态: 1发布 0下线',
    publish_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发布时间',
    admin_id     INT                                     COMMENT '发布管理员ID',
    FOREIGN KEY (admin_id) REFERENCES admin_user(admin_id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统公告表';


-- ================== 性能索引 ==================

CREATE INDEX idx_doctor_dept_id        ON doctor(dept_id);
CREATE INDEX idx_doctor_status         ON doctor(status);
CREATE INDEX idx_schedule_doc_id       ON schedule(doc_id);
CREATE INDEX idx_schedule_date         ON schedule(work_date);
CREATE INDEX idx_schedule_query        ON schedule(work_date, doc_id, status);
CREATE INDEX idx_appt_patient          ON appointment(patient_id, status);
CREATE INDEX idx_appt_schedule         ON appointment(schedule_id);
CREATE INDEX idx_appt_status           ON appointment(status);
CREATE INDEX idx_payment_status        ON payment_record(pay_status, create_time);
CREATE INDEX idx_change_request_status ON schedule_change_request(status, apply_time);
CREATE INDEX idx_notice_status         ON sys_notice(status, is_top, publish_time);
```

## 三、关键状态码说明

### 1. 科室、医生、管理员状态

```text
1 正常
0 停用
```

停用不等于删除。科室或医生停用后，不再出现在患者可预约列表中，但历史预约记录仍然可以通过外键正常查询。

医生和管理员账号停用后不允许登录：

```text
doctor.status = 0：医生账号禁止登录，提示“账号已停用，请联系管理员”
admin_user.status = 0：管理员账号禁止登录
```

患者表当前不设置 `status` 字段，因此暂不涉及患者账号停用规则。

### 2. 排班状态

```text
1 正常
0 停诊
```

排班停诊后，患者不能继续预约该排班。本方案中，停诊申请只允许在该排班没有有效预约时提交和通过。

### 3. 预约状态

```text
1 已预约
2 已取消
3 已就诊
4 已过期
```

取消和过期不合并。取消通常由患者主动操作，过期通常由系统根据排班日期和时段自动标记，二者业务含义不同。

### 4. 排班变更申请状态

```text
1 待审核
2 已通过
3 已驳回
4 已撤回
```

医生提交申请后，所有有审核权限的管理员都可以看到待审核申请。申请不需要指定给某一个管理员，实际处理人记录在 `audit_admin_id` 中。

### 5. 模拟支付状态

```text
0 待支付
1 已支付
2 已关闭
```

`payment_record` 只记录挂号费模拟支付结果，不调用真实支付接口，不处理第三方交易流水和退款。

## 四、设计说明
### 1. 停诊申请的有效预约校验

为了避免停诊后需要批量取消患者预约，本方案规定：医生发起停诊申请时，该排班不能存在有效预约。

有效预约定义为：

```text
appointment.status = 1 已预约
```

医生提交停诊申请时先检查：

```sql
SELECT COUNT(*)
FROM appointment
WHERE schedule_id = ?
  AND status = 1;
```

如果结果大于 0，则禁止提交停诊申请，并提示“该排班已有患者预约，不能申请停诊”。

由于提交申请后到管理员审核前，患者仍可能预约该排班，因此审核通过时还必须再次检查：

```sql
SELECT COUNT(*)
FROM appointment
WHERE schedule_id = ?
  AND status = 1;
```

只有提交时和审核时均不存在有效预约，系统才允许将 `schedule.status` 修改为 `0`。

### 2. 修改排班申请的设计

`change_type = 2` 表示修改排班。一次修改排班申请可以同时修改日期、时段和总号源。

```text
target_work_date 不为空：申请修改出诊日期
target_shift 不为空：申请修改出诊时段
target_total_quota 不为空：申请修改总号源
```

修改排班申请必须至少填写一个目标字段，否则没有实际修改内容。

修改排班时需要校验：

```text
1. 如果修改日期或时段，要检查同一医生在目标日期和目标时段没有已有排班，且该排班没有有效预约。
2. 如果修改总号源，新总号源不能小于已预约人数。
```

上述校验应该在医生发送申请时校验一次，管理员审核通过时再校验一次。这是因为【医生申请】和【管理员审核】之间存在时间差。

有效预约数量可以通过以下方式计算：

```sql
SELECT COUNT(*)
FROM appointment
WHERE schedule_id = ?
  AND status = 1;
```

如果没有有效预约，日期、时段、总号源均可修改。如果已有有效预约，则只能修改总号源，不能修改日期和时段。

### 3. 审核通过后自动调整排班

管理员审核通过后，系统应根据申请类型自动修改 `schedule` 表，管理员不需要再手动维护一次排班。

```text
change_type = 1 停诊：
    schedule.status = 0

change_type = 2 修改排班：
    如果 target_work_date 不为空，则更新 schedule.work_date
    如果 target_shift 不为空，则更新 schedule.shift
    如果 target_total_quota 不为空，则更新：
    schedule.total_quota = target_total_quota
    schedule.rest_quota = old_rest_quota + (target_total_quota - old_total_quota)
```

修改总号源时必须保证：

```text
0 <= 新 rest_quota <= 新 total_quota
```

如果新总号源小于已预约人数，审核通过应失败。

### 4. 多管理员同时审核如何避免冲突

审核时使用基于状态字段的乐观并发控制。只有 `status = 1` 的待审核申请允许被处理：

```sql
UPDATE schedule_change_request
SET
    status = 2,
    audit_admin_id = ?,
    audit_time = NOW(),
    audit_remark = ?
WHERE request_id = ?
  AND status = 1;
```

如果影响行数为 1，说明审核成功；如果影响行数为 0，说明该申请已经被其他管理员处理，应提示“申请已被处理”。

通过审核后修改申请状态和修改 `schedule` 表必须放在同一个事务中：

```text
BEGIN;

1. 查询并校验申请仍为待审核状态
2. 根据申请类型做业务校验，例如停诊时再次检查有效预约，修改排班时检查目标时段冲突和号源数量
3. 条件更新 schedule_change_request，要求 status = 1
4. 如果影响行数为 1，根据申请内容更新 schedule
5. 如果影响行数为 0，ROLLBACK

COMMIT;
```

这样即使两个管理员同时审核同一条申请，数据库也只会允许其中一个成功。

### 5. 排队号设计

`appointment.queue_number` 表示患者在某个排班下的就诊排队号。为了避免同一个排班下出现重复号码，必须增加唯一约束：

```sql
UNIQUE (schedule_id, queue_number)
CHECK (queue_number > 0)
```

生成排队号时可以根据当前排班下已有最大排队号加 1，实际实现中应放在事务内处理。

### 6. 模拟支付记录设计

`payment_record` 用于记录挂号费模拟支付。患者预约成功后，系统根据排班挂号费生成一条待支付记录；患者点击“模拟支付”按钮后，系统将支付记录更新为已支付。

```text
预约创建：
    创建 appointment
    创建 payment_record，pay_status = 0

模拟支付：
    payment_record.pay_status = 1
    payment_record.pay_time = NOW()
```

本方案不把 `patient_id` 存入 `payment_record`，因为支付记录已经通过 `appt_id` 关联到预约表，而预约表中已有 `patient_id`：

```text
payment_record.appt_id
    -> appointment.appt_id
    -> appointment.patient_id
```

如果在支付表中重复保存 `patient_id`，可能出现支付记录患者和预约记录患者不一致的问题。查询某患者支付记录时通过联表完成：

```sql
SELECT p.*
FROM payment_record p
JOIN appointment a ON p.appt_id = a.appt_id
WHERE a.patient_id = ?;
```

模拟支付不改变预约状态。本系统仍然使用：

```text
appointment.status = 1 已预约
```

表示预约有效；`payment_record.pay_status` 只表示挂号费模拟支付状态。

### 7. 金额和排班变更目标字段约束

挂号费和模拟支付金额不能为负数：

```sql
CHECK (schedule.fee >= 0)
CHECK (payment_record.amount >= 0)
```

排班变更申请中的目标时段和目标总号源如果填写，必须满足排班字段的同类约束：

```sql
CHECK (target_shift IS NULL OR target_shift IN ('上午', '下午', '夜诊'))
CHECK (target_total_quota IS NULL OR target_total_quota > 0)
```

## 五、升级后的合理性总结

本方案相比原 5 表设计增加了数据库复杂度，但仍然保持在挂号预约主题内：

1. `admin_user` 补齐管理员角色，管理员账号密码改为数据库存储，密码使用 BCrypt 哈希。
2. `department.status`、`doctor.status` 支持停用而非删除，保护历史数据完整性。
3. `doctor.avatar_url`、`doctor.specialty` 改善患者选择医生时的信息展示。
4. `schedule.status`、`schedule.fee` 增强排班管理能力。
5. `appointment.queue_number`、`cancel_reason`、`update_time` 增强预约记录的业务表达。
6. `payment_record` 支持挂号费模拟支付记录，增加挂号流程完整性，但不引入真实支付系统复杂度。
7. `schedule_change_request` 支持医生停诊申请和修改排班申请；修改排班可同时调整日期、时段和总号源。
8. `sys_notice` 支持公告、停诊通知和系统消息发布。

因此，该设计比原始 5 表结构更完整，也比包含病历、处方、药品、真实支付的完整诊疗方案更贴合“医院预约挂号系统”的项目定位。
